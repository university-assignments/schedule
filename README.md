# Расписание

Расписание группы ЮУрГУ с журналом изменений: что и когда переставили, а не только то,
как выглядит неделя сейчас.

Страница: <https://university-assignments.github.io/schedule/>

Серверной части нет. Данные лежат в этом же репозитории обычными JSON-файлами, а
страница — статическая сборка Vite на GitHub Pages.

## Как это устроено

```
public/data/
├── groups.json             список групп: GUID в СУСУ, слаг для ссылки, название
├── meta.json               отметки времени по каждой группе — по ним обходится кэш Pages
├── schedule/<guid>.json    дамп ответа API как есть
└── changes/<guid>.json     журнал правок, только дописывается
```

`scripts/fetch_schedule.py` просит у гейтвея расписание каждой группы, сравнивает с
дампом в репозитории и дописывает расхождения в журнал.

Сравнение разбирает правки от точных к приблизительным: полностью совпавшие пары
отбрасываются, среди оставшихся ищется совпадение по дате+времени+предмету (это
«изменено»), затем по дате+предмету («перенесено»), и лишь остаток становится честными
«добавлено» и «удалено». Без этого перенос пары попадал бы в журнал двумя записями.

## Добавить группу

1. Узнайте GUID: откройте расписание группы на online.susu.ru, в DevTools → Network
   найдите запрос `GetGroupSchedule/<guid>`.
2. Допишите её в `public/data/groups.json`:

```json
{ "id": "<guid>", "slug": "ke-402", "name": "КЭ-402", "mine": false }
```

`slug` попадает в адрес (`?group=ke-402`) — им и делятся ссылкой. `mine: true` у одной
группы означает «открывать по умолчанию».

3. Обновите расписание (см. ниже) — дамп появится сам.

## Обновить расписание

```bash
pip install -r scripts/requirements.txt
SUSU_TOKEN='eyJ...' python scripts/fetch_schedule.py --dry-run
SUSU_TOKEN='eyJ...' python scripts/fetch_schedule.py
```

`--dry-run` ничего не пишет и только показывает, что изменилось бы.

Журнал изменений и `meta.json` пишет только скрипт: дамп, заменённый в обход него, в
журнал не попадёт, а отметка «Обновлено» на странице не сдвинется.

Данные едут внутри сборки, поэтому на странице они появятся только после публикации
(см. ниже).

## Доступ к API

Гейтвей отвечает только на запрос с заголовком `Authorization: Bearer <JWT>`; без него
приходит 404, а не 401, поэтому адрес в браузере открывается «несуществующей страницей».

Токен берётся в DevTools из заголовка `Authorization` запроса `GetGroupSchedule/<guid>`
и живёт около суток. Вместо него скрипт принимает `SUSU_LOGIN`, `SUSU_PASSWORD` и
`SUSU_AUTH_URL` (адрес эндпоинта входа, ищется в DevTools → Network при логине) и сам
меняет их на свежий токен.

## Публикация

```bash
pnpm run deploy
```

Скрипт собирает страницу и заливает `dist/` в ветку `gh-pages`; первый запуск сам её
создаёт. Pages раздаёт эту ветку как есть: Settings → Pages → Source — «Deploy from a
branch», `gh-pages`, `/ (root)`.

Именно `pnpm run deploy`: `pnpm deploy` без `run` — встроенная команда pnpm, а не этот
скрипт.

Зачем скрипту флаги `gh-pages`:

- `--dotfiles` везёт в ветку `.nojekyll`. Без него Pages прогонит сборку через Jekyll, а
  тот выбрасывает файлы, имя которых начинается с `_`.
- `--remove` с шаблоном `{**,**/.*,.!(git)/**}` перед заливкой чистит ветку целиком. По
  умолчанию gh-pages стирает только файлы без точки в начале имени, а первый запуск
  создаёт ветку из рабочего дерева `main` — без шаблона `.gitignore`, `.npmrc`, `.claude/`
  и прочее остались бы в ней навсегда.

## Разработка

```bash
pnpm install
pnpm dev          # http://localhost:8030/schedule/
pnpm type-check
pnpm lint
pnpm build
```

Стек: Vue 3 + TypeScript, Vite, Tailwind 4, TanStack Query (кэш и обновление по возврату
на вкладку), TanStack Table (сортировка и видимость колонок), Pinia (личные настройки в
localStorage), zod (проверка формы JSON при загрузке), dayjs.

Маршрутизация — на хэше: GitHub Pages не умеет отдавать `index.html` на произвольный
путь, и ссылка вида `/schedule/changes` упиралась бы в его собственную 404.

Фильтры и показанная неделя живут в адресной строке — ссылкой можно поделиться вместе с
выбранным видом. Личные настройки («Мои пары», колонки) в адрес не уезжают: иначе
однокурсник из другой подгруппы открыл бы ссылку с чужим списком предметов и не заметил
подмены.

Открывается страница на текущей неделе, стрелки листают её шагом выбранного периода.
Режим «Свой» меняет стрелки на два поля дат; любую из границ можно оставить пустой —
получится «с 1 декабря и дальше». Календарь ограничен теми числами, на которые вообще
есть данные.

Отдельно запоминается последняя просмотренная неделя — на десять минут: случайное
обновление страницы не должно сбрасывать на сегодня, но и назавтра расписание обязано
открыться на текущем дне, а не там, где его закрыли вчера.

## Подгруппы

Признака подгруппы в ответе API нет. Есть только две пары в одно и то же время — так
деление и выглядит в данных. Такие пары помечены значком `⇄`, а «Мои пары» — ручной
список предметов, который хранится в браузере.
